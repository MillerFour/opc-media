API Key 的边界：浏览器持有 · 请求即焚 · 连接层堵 SSRF generator.go / tryon.go
Key 生命周期client_config
1
存在浏览器，不进后端
设置中心保存 provider / baseURL / apiKey / model，只落在当前浏览器；共享设备用完点"清除本地配置"。
2
随单次请求发送
请求体带上 client_config，后端 NewGeneratorFromClientConfig() 只在本请求内存里构造适配器。
3
不落任何持久层
不进配置文件、不进数据库、不进业务日志；ComfyUI 分支干脆不接受 client_config——本地工作流一旦允许用户填地址，就是给人递内网跳板。
4
错误即焚
生成失败只回 "换装生成失败，请稍后重试"，原始 error 不透传——供应商报错体可能带着完整 Base URL。
同样的问题，两种解法
用户自备模型 → 配置校验 + 连接层封锁
本地 ComfyUI → 不接受用户配置，只认服务端
用户可控 Base URL 的三层校验validateClientModelConfig + DialContext
①字符串层
必须 http/https · 不允许带账号、查询参数、片段 · 不允许 localhost / *.localhost · 长度上限（Key 4096 / URL 2048）
②IP 层
域名先解析成 IP 再逐个判：loopback / 私网 / 链路本地 / 未指定地址——全是私网直接拒绝，不给"部分命中"留口子
③连接层（兜底）
在 DialContext 里重新解析、直接拨 IP，绕过一切上层缓存；transport.Proxy = nil —— 用户可控地址走系统代理，代理会替你去访问内网，前两层全白做
会被拒绝的地址（示例）
http://localhost:11434　http://127.0.0.1:8188
http://192.168.1.10:8000　http://10.0.0.5:9000　169.254.x.x
